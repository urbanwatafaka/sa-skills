# Блок: диаграммы

Общие соглашения для всех секций с диаграммами и для скилов `puml-*`.

## Когда

У секции в выводе `sa_draft.py plan` колонка «диаграммы» не пуста и в секции есть процесс, структура или модель, которые без картинки читаются хуже. Нечего рисовать — диаграмму не делай.

## Структура

- Файл: `draft/diagrams/<id секции>-<вид>.puml`, вторая диаграмма того же вида — `-2`. Пример: `draft/diagrams/02-architecture-sequence.puml`.
- В секции — отдельная строка `@diagram diagrams/<файл>.puml`; при сборке она заменяется блоком кода `plantuml` (в Confluence — макрос PlantUML, не картинка и не исходный текст).
- Под sequence-диаграммой процесса — «Описание шагов» с отсылками `**Шаги [00X]-[00Y]**` по номерам `autonumber`.

| Что показать | Скил | Где в ТЗ |
|---|---|---|
| Контейнеры системы и связи (C2) | `puml-c2` | `02-architecture`, открыто |
| Вызовы между сервисами по шагам | `puml-sequence` | `02-architecture`, под «Раскрыть» процесса |
| Таблицы и связи | `puml-er` | `03-changes` → «3. БД» |
| Логика с ветвлениями, смена статусов | `puml-activity`, `puml-state` | вне канона типа 1, по просьбе аналитика |

## Правила

- Диаграмма визуализирует факты из артефактов задачи, а не новый синтез: каждый участник, таблица и стрелка опирается на строку карты влияния, источник, решение `D-xx` или роль BRD. Не хватает факта — вопрос, а не догадка.
- Новое — красным, только в ТЗ на доработку и только для того, что ещё не реализовано (влияние `новый`/`изм.` в карте): `A [#red]-> B: <color:red>Текст</color>`. Реализованное красным не выделяется. На C2 цвета нет, если аналитик не попросил.
- Цвет по имени — без `#`: `<color:red>`, не `<color:#red>`; `#` — только с HEX (`<color:#FF0000>`).
- Перенос `\n` внутри цветного текста — отдельный тег на каждую строку: `<color:red>Строка 1</color>\n<color:red>Строка 2</color>`.
- `!include`/`!includeurl` — только полный `https://` URL, не локальный путь и не `<C4/...>`.
- Метод на стрелке — `ГЛАГОЛ /префикс/путь` реального или спроектированного метода, не пересказ. Метода в коде нет и сценарий новый — спроектируй метод и добавь его в «Доработки».
- Таблица БД — `схема.таблица` одним токеном.
- Kafka на sequence — участник `queue`, стрелки от сервиса к нему с подписью `<топик> — <Событие>`. Kafka на C2 — без узла: пунктирная стрелка `$tags="kafka"` прямо от продюсера к каждому консьюмеру с подписью `N) Kafka: <топик> — <Событие>`; HTTP — сплошные. Топик — как в коде и в «Топиках Кафка», не согласован — `ХХХХХ`.
- Проверка: `python3 <плагин>/scripts/sa_puml.py check <файл>`; без PlantUML проверяется только структура — напиши об этом в итоге.

## Чек-лист

- [ ] Нет участников вне карты влияния и ролей BRD.
- [ ] Красным выделено только нереализованное, цветовые теги валидны.
- [ ] Все `!include` — полные `https://` URL.
- [ ] Шаги в тексте и на диаграмме совпадают.
- [ ] `sa_puml.py check` вернул `OK`.
