# Блок: справочники и адаптер платёжного метода

Дополнение к `blocks/changes.md` для секции `03-changes` шаблона `integration`. Эталон оформления — Confluence 110167970 (Яндекс СБП).

## Когда

Всегда в ТЗ на интеграцию платёжного метода: в доработках `payment.paymentmethods`, адаптера провайдера и `Platform.Pf2xPf1.Adapter`; в доработке `Platform.Partner.Adapter` — если метод передаётся при создании мерчанта из анкеты.

## Справочники `payment.paymentmethods`

В «3. БД» — по таблице «Поле | Значение» на каждую новую строку; над таблицей — строка с именем таблицы в обратных кавычках. Несколько строк одной таблицы — колонками (`| Поле | Платёжная страница | Настройки канала |`).

````markdown
`PaymentProviders`

| Поле | Значение |
|---|---|
| `Id` | `abaf24fc-f078-4029-ba73-a737437cd625` |
| `Code` | `BlueWhale` |
| `Name` | Blue Whale |
| `Type` | `PaymentSystem` |
| `IsActive` | `true` |

`PaymentMethods`

| Поле | Значение |
|---|---|
| `Id` | `7a409702-93a6-4347-8ee5-2f7294d87400` |
| `ProviderId` | `abaf24fc-f078-4029-ba73-a737437cd625` |
| `PaymentMethodCode` | `ApmOpenBankingBlueWhale` |
| … | … |
````

- Таблицы: `PaymentProviders` (если провайдера ещё нет), `PaymentMethods`, `PaymentMethodLocalizations`, `GroupViews` и `GroupViewPaymentMethods` (если метод в новой группе). Поля — все колонки таблицы по схеме сервиса, кроме служебных (`CreatedAt`, `UpdatedAt`, `ConcurrencyToken`).
- `Id` новых строк — новые GUID, их задаёт аналитик в ТЗ. У `GroupViewPaymentMethods` своего `Id` нет, ключ составной (`GroupViewId`, `PaymentMethodId`) — так и написать.
- Есть ли провайдер в `PaymentProviders`, проверяй по коду сервиса и по статье 37138968, а не по карточке; нет — новая строка.
- `ShortDescription` — ключ локализации; `PaymentMethodLocalizations.PaymentMethodShortDescription` — код метода. Английское краткое описание хранится не в таблице локализации (там только `NameRu`, `NameEn`), — укажи, где: ключи `en-US` фронта.
- `AdditionalSettings` — JSON из BRD («Данные для статьи «Платежные методы»»), в таблице — ссылка на него, не копия.

## Адаптер провайдера

Новый адаптер описывается четырьмя таблицами после списка «1. Описание изменений»; внутренние и внешние методы не смешиваются.

| Таблица | Колонки | Что в ней |
|---|---|---|
| **Входящие методы** | Метод и путь · Тело · Поведение | Методы, которые вызывает общий адаптер (`payment.apm.adapter`, `payment.card.adapter`) по контракту реализации |
| **Обратные вызовы в <общий адаптер>** | Метод и путь · Назначение | Чем адаптер возвращает статусы заявки и возврата |
| **Внешние методы <провайдер>** | Метод · Когда · Запрос · Ответ | Полный URL провайдера, когда вызывается (п.N), поля запроса и ответа |
| Поля `<главный запрос>` | Поле провайдера · Значение | Откуда берётся каждое поле запроса создания платежа |

- Ниже таблиц — формат callback (поля, статусы, `state`) и правило подписи запросов и callback.
- Источник полей — swagger или документация провайдера; ссылка на источник — в строке над таблицей. Чего нет в документации — `⚠ Q-SA-xx`, не догадка.
- Swagger провайдера можно приложить под `:::expand Swagger <провайдер>` блоком `@openapi`.
- Блоки вида «в технической реализации это будет (нагенерено, не проверила)» не пишутся: всё, что не проверено, — вопрос.

## Маппинг `Platform.Pf2xPf1.Adapter`

В «3. БД» — таблицы `payment_methods_mapping` (одна строка) и `payment_methods_mapping_mcc` (строка на каждый тип мерчанта ПФ1, колонками), поле — значение. Значения ПФ1, которых нет в коде, — «из БД ПФ1» с решением `D-xx`, по образцу метода-аналога.

````markdown
`payment_methods_mapping`

| Поле | Значение |
|---|---|
| `id` | `10ae4704-428e-490d-819c-c545e7770664` |
| `pf1_code` | `Prodamus:openbank_blue:eur` |
| `pf2_paymentMethodCode` | `ApmOpenBankingBlueWhale` |
| `pf1_aggregator` | `openbank_blue` |
| … | … |
````

## Чек-лист

- [ ] Есть таблицы `PaymentMethods` и `PaymentMethodLocalizations`; провайдер и группы — если новые.
- [ ] У каждой новой строки GUID; значения ПФ1 без источника — «из БД ПФ1».
- [ ] Значения метода совпадают с «Данными для статьи «Платежные методы»» в BRD.
- [ ] У адаптера — таблицы входящих методов, обратных вызовов, внешних методов и полей запроса; формат callback и подпись описаны.
- [ ] Агрегатор и коды ПФ1 названы одинаково во всём ТЗ.

`sa_validate.py` проверяет наличие таблиц `PaymentMethods`, `PaymentMethodLocalizations` и GUID в полях-идентификаторах.
