# Блок: топики Кафка

Секция `04-kafka` — подраздел `##` в конце «Доработок», отделён горизонтальной чертой (её ставит сборка).

## Когда

Доработка добавляет топик или меняет состав сообщения. Иначе секции нет — файл не создаётся.

## Структура

```markdown
## Топики Кафка

| Топик | Сценарий | Продюсер | Консьюмер | DTO | Комментарий |
|---|---|---|---|---|---|
| `lkp.questionnaire` | Анкета сохранена | `lkp-back` | `partners-dashboard` | {{DTO:QuestionnaireSavedEvent}} | Новое поле `promocodeOwnerInn` ‹IM-04› |
```

Файл `draft/dto/QuestionnaireSavedEvent.json`:

```json
{
  "key": "8f0c…",
  "payload": {"questionnaireId": 123, "promocodeOwnerInn": "7701234567"},
  "$type": "QuestionnaireSavedEvent"
}
```

## Правила

- Одна строка — одно сообщение (Command или Event); таблица одна на все топики доработки.
- В ячейке DTO — плейсхолдер `{{DTO:<ИмяDTO>}}`, JSON — файл `draft/dto/<ИмяDTO>.json`. При публикации ячейка становится макросом «Код» (`json`, заголовок — имя DTO, свёрнут). Голое имя класса в ячейке — ошибка.
- JSON — как сериализует платформа: camelCase, `key`, поля сообщения (у классов с `Payload` — объект `payload`), `$type` = имя класса. Структура — из реального класса, не придумывается. Для громоздких неизменных сообщений — сокращённый пример и в «Комментарии», что опущено.
- Имя топика или DTO ещё не согласовано — `ХХХХХ` в ячейке и `⚠ Q-SA-xx`.

## Чек-лист

- [ ] Каждый `IM-xx` вида `Kafka` в скоупе есть в таблице.
- [ ] У каждой строки указаны продюсер, консьюмер и DTO.
- [ ] Для каждого `{{DTO:…}}` есть файл `draft/dto/<имя>.json` с `$type`.
