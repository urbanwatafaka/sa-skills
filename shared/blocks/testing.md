# Блок: тестирование и регресс

Секция `08-testing`.

## Когда

Всегда.

## Структура

```markdown
# Тестирование и регресс

## Новое поведение

1. Анкета с собственным промокодом партнёра — ответ `422`, анкета не сохранена. ‹R-01›
2. `partners-dashboard` не ответил за 3 с — анкета сохранена без проверки. ‹D-02›

## Сохраняемое поведение

- Анкета с промокодом другого партнёра сохраняется, промокод привязывается к анкете. ‹R-01›
- Анкеты, сохранённые до релиза, не перепроверяются и вознаграждения по ним не пересчитываются. ‹D-01›
```

## Правила

- Две явно различимые части: «Новое поведение» и «Сохраняемое поведение».
- Сохраняемое поведение — конкретное условие, режим или статус и как именно он работает, не «работает как раньше» и не «регресс не ожидается».
- Полнота пропорциональна числу затронутых механизмов: по каждому изменённому крону, методу, ветке логики — свои пункты о ветках, которые не меняются.
- Отдельного раздела «Регресс» нет; в критериях приемки User Stories регресса тоже нет.
- Ветки ошибок и недоступности смежных сервисов (таймаут, повтор, нет прав, конфликт данных) — пунктами «Нового поведения».

## Чек-лист

- [ ] Есть обе части.
- [ ] Каждый пункт сохраняемого поведения называет условие и конкретное поведение.
- [ ] Для каждого вызова смежного сервиса проверена его недоступность.
- [ ] Каждый изменённый механизм имеет свои пункты регресса.
