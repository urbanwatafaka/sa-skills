# Блок: условия релиза

Секция `09-release` — между «Тестирование и регресс» и «Открытые вопросы». Текст — фиксированный релизный регламент компании.

## Когда

Проверяется на каждой сборке по двум условиям, независимо друг от друга. Секция создаётся, если применимо хотя бы одно; иначе её нет.

1. Доработка добавляет или меняет функционал в интерфейсах ЛК и/или БО — сверяй с «Требованиями к UI» и `Front`-подразделами «Доработок».
2. Доработка создаёт или меняет тексты уведомлений для мерчантов или их сотрудников (email, push, SMS) — сверяй с письмами в «Доработках» и топиками с уведомлениями.

Оба условия сверяются с собранным документом, а не только со словами аналитика.

## Структура

```markdown
# Условия релиза

:::warning
Доработка меняет функционал ЛК и/или БО (<конкретный раздел>) — нужна инструкция в help по этому функционалу со ссылкой в этом документе. **Без этого релиз не состоится.** Пингануть Маркетинг в чате на обновление help, подсветить это для РО с указанием задачи.
:::

:::warning
Доработка вводит/меняет тексты уведомлений для <кому конкретно> (<какие именно уведомления>) — тексты нужно согласовать с КС (Князева, Федоткина). **Без согласования релиз не состоится.**
:::

Оба пункта — чеклистом в задаче в Jira (на аналитика); если чеклиста нет — добавить.
```

## Правила

- Каждое применимое условие — отдельный `:::warning` с текстом дословно; меняются только места в угловых скобках.
- После блоков — один обычный абзац про чеклист в Jira: «Оба пункта …» или «Этот пункт …». Если по всем сервисам `Задача: <Не заведена>` — так и написать: «задача пока не заведена ни по одному сервису, при заведении добавить чеклист туда же».
- Если применимо условие 2, вопрос о том, кто согласует тексты этих уведомлений, в «Открытых вопросах» не дублируется: открытый такой вопрос в `questions.md` закрой статусом `— *obsolete*` с решением `D-xx` «дублирует «Условия релиза», согласует КС» и назови его одной строкой в итоге аналитику. Вопрос о самом содержании текста («что написать в письме») — не дубль, его не трогай.

## Чек-лист

- [ ] Оба условия проверены по собранному документу.
- [ ] Текст каждого блока совпадает с регламентом.
- [ ] Абзац про чеклист в Jira учитывает, заведены ли задачи.
- [ ] При условии 2 вопрос «кто согласует тексты» закрыт и назван в итоге.
