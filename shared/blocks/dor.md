## Правила

- Колонки обеих таблиц — `№ | Поле | Значение | Ответственный`.
- Каждое значение — с трассировкой `‹R-xx, D-xx›`; значения из кода — решением `D-xx` с источником в `decisions.md`, ссылка `файл:строка` в ТЗ не попадает.
- Секреты (MID, ключи, пароли, тестовые карты) в ТЗ не пишутся — только где лежат.
- «Данные для статьи «Платежные методы»» — три строки: «Платежный провайдер» (`Code`, `Name`, `Type`), «Платежный метод» (`PaymentMethodCode`, `MethodType`, `Currency`, `Title`, `ShortDescription`, `ShortDescriptionEoo`, `FullDescription`, `LogoUrl`), «Additional_Settings» (JSON под `:::expand additional_settings`). Значения совпадают с таблицами справочников в «Доработках» (`blocks/payment-method.md`).
- `ShortDescription` — ключ локализации (как `CardInt`, `ApmSbpSbp`, или код метода), не текст; текст для покупателя — `Title`, `ShortDescriptionEoo`, `FullDescription`.
- Логотип не утверждён — `LogoUrl`: `null` и `⚠ Q-PO-xx`, не ссылка «из вложения карточки».

## Чек-лист

- [ ] «Описание интеграции» — 22 строки шаблона DoR по порядку, пустых значений нет, у каждой строки ответственный.
- [ ] Неизвестное — `⚠ Q-…`, неприменимое — «Не применяется: …».
- [ ] В «Данных для статьи» есть провайдер, метод со всеми полями и JSON `Additional_Settings`.
- [ ] `ShortDescription` — ключ локализации; английские название и описание заданы.
- [ ] Секретов в тексте нет.
