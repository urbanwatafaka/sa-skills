# Блок: архитектура и процесс

Секция `02-architecture`. Диаграммы — `shared/blocks/diagrams.md`, скилы `puml-c2` и `puml-sequence`.

## Когда

Всегда: одна C2-схема на документ и по процессу на каждый независимый сценарий.

## Структура

```markdown
# Архитектура и Процесс

## C2 — Архитектура

@diagram diagrams/02-architecture-c2.puml

## Процессы

:::expand Процесс: Проверка промокода при сохранении анкеты
@diagram diagrams/02-architecture-sequence.puml

### Описание шагов

1. Мерчант сохраняет анкету с промокодом. **Шаг [001]**
2. `lkp-back` проверяет владельца промокода в `partners-dashboard`: `GET /internal/promocodes/{code}/owner`. ‹IM-01, R-01› **Шаги [002]-[003]**
3. Промокод принадлежит самому партнёру — анкета не сохраняется, мерчант видит текст ⚠ Q-PO-02. **Шаги [004]-[005]**
:::
```

## Правила

- C2 — одна на весь документ, открыто, не под «Раскрыть». Нужна, только если без неё доработку не понять.
- Каждый независимый процесс — свой блок `:::expand Процесс: <название>` внутри `## Процессы`; внутри — sequence-диаграмма, под ней `### Описание шагов`. Вторая диаграмма того же вида — `02-architecture-sequence-2.puml`.
- «Описание шагов» — нумерованный список: сначала что происходит человеческим языком, в конце **каждого** пункта — жирная отсылка `**Шаг [00X]**` или `**Шаги [00X]-[00Y]**` ровно к тем шагам, которые он описывает. Номера — из `autonumber "<b>[000]"` диаграммы: печатает их `python3 <плагин>/scripts/sa_puml.py steps <файл>`, вручную не считай. Валидатор проверяет, что отсылок за пределами диаграммы нет и каждый шаг описан хотя бы одним пунктом.
- Метод в тексте — HTTP-глагол заглавными, пробел, полный путь с `/` и префиксом раздела: `GET /internal/users/find`; маршрут без префикса — префикс из группы Swagger метода.
- Между «Описанием шагов» и разделом «Доработки» нет лид-абзаца «Доработка: …». Исключение — систему нужно создать целиком: макрос `:::info` с этой пометкой сразу под «Описанием шагов» процесса.
- `Задача:` и разбивка Front/Back внутри процессов не повторяются — они один раз в `03-changes`.
- Таблица БД в тексте — слитно `схема.таблица`: `lkp.questionnaires`.

## Чек-лист

- [ ] C2 одна и не под «Раскрыть»; каждый процесс — под своим «Раскрыть».
- [ ] Каждый пункт «Описания шагов» заканчивается жирной отсылкой к своим шагам.
- [ ] Шаги в тексте и на диаграмме совпадают, лишних и пропущенных нет.
- [ ] Методы записаны как `ГЛАГОЛ /префикс/путь`.
