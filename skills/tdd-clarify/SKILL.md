# /tdd-clarify [KEY] <ответы | целевое поведение | ссылки>

Входы: `questions.md`, `decisions.md`, `context.md`, ввод аналитика. Из `sources/BRD.md` и `impact-map.md` — только строки нужных `R-xx` и `IM-xx` (grep по ID), файлы целиком не читай. Выход: `questions.md`, `decisions.md`, `context.md` (строки `?` в `## Границы`).

`<база>` — базовая директория этого скила, `<плагин>` = `<база>/../..`. Все команды — из рабочей папки аналитика.

Файлы задачи читай и пиши только по абсолютному пути `<tasks_dir>/<KEY>/…` (`tasks_dir` — из `sa_paths.py`), даже если ниже файл назван коротко (`questions.md`, `sources/BRD.md`).

## Перед началом

Прочитай `<плагин>/shared/rules/ai-rules.md`, `<плагин>/shared/rules/artifact-writing.md`, `<плагин>/shared/rules/question-routing.md` и в `<плагин>/shared/schemas/artifacts.md` разделы context.md, questions.md и decisions.md.

Вопросы, ссылки, ID и таблицы пиши по `artifact-writing.md`. Статус существующего вопроса меняй на той строке, где стоит маркер: `*open*`/`*open, blocking*` на `*answered*` или `*obsolete*`; текст не правь. Вопрос, стоящий за строкой `?` в «Границах», — всегда `— *open, blocking*`.

## Шаги

1. **Папка задачи.** `python3 <плагин>/scripts/sa_paths.py` — возьми `tasks_dir`. Первый аргумент похож на ключ (`[A-Z][A-Z0-9]+-[0-9]+`) — `tasks/<KEY>`; иначе единственная задача в `tasks/`, при нескольких — спроси. `python3 <плагин>/scripts/sa_status.py tasks/<KEY>`: стадия должна быть `start`, `clarify`, `draft` или `check`, иначе скажи, какую стадию запустить сначала, и остановись. В «Устаревших входах» есть `context` или `impact-map` — предупреди, что контекст или карта менялись после прошлого уточнения, и учитывай их новую версию в анализе.
2. **Разбор ввода.**
   - Ответ с ID («Q-PO-02: …») — сопоставь напрямую. Без ID — по смыслу; если ответ подходит к нескольким вопросам или ни к одному, перечисли варианты и спроси.
   - Описание целевого поведения — решения аналитика: каждое отдельное правило — своё решение с `← Q` = `—` и «Кто/где» = «аналитик».
   - Ссылки — прочитай по `<плагин>/shared/access/adapters.md` только нужное, выжимку сохрани в `sources/<короткое-имя>.md`.
3. **Решения.** ID решений: `python3 <плагин>/scripts/sa_ids.py next tasks/<KEY> D <N>`, N — по числу новых решений (N=0 — без вызова). На каждый ответ — строка в `decisions.md`; дата — сегодня (ГГГГ-ММ-ДД), «Кто/где» — со слов аналитика («PO, чат ММ»), без источника — «аналитик». Если `decisions.md` нет — создай только с заголовком и шапкой таблицы; если есть — только дописывай строки, существующие не меняй:

   ```markdown
   # Журнал решений

   | ID | ← Q | Решение | Кто/где | Дата |
   |---|---|---|---|---|
   ```

   Образец строки (placeholder-ID): `| D-xx | Q-PO-xx | Что решили, одной-двумя фразами | PO, чат ММ | ГГГГ-ММ-ДД |`. Образец не записывай — в файле только реальные решения.

   `← Q` — ровно один ID вопроса (`Q-PO-xx`/`Q-SA-xx`) или `—`. Один ответ закрывает несколько вопросов — отдельная строка `D-xx` на каждый вопрос. Вопрос, на который ответ полный, — статус `— *answered*`. Ответ частичный — вопрос остаётся открытым, недостающее заведи новым вопросом со ссылкой на старый в тексте.

   **Скоуп.** Если решение закрывает строку `?` в `## Границы` `context.md` (в Комментарии строки указан отвеченный вопрос) — обнови эту строку на месте: `Скоуп` = `в скоупе` или `вне скоупа`; Комментарий — `—` для `в скоупе`, для `вне скоупа` причина со ссылкой на `D-xx`. Строка не должна остаться `?` после решения. Если вопрос строки `?` стал `*obsolete*` без решения о скоупе — строка остаётся `?`: заведи новый блокирующий вопрос о скоупе вместе с вопросами шага 4 (одна пачка, отдельного вызова нет) и впиши его ID в Комментарий. Новый вопрос о скоупе — строка `?` в `## Границы` с его ID в Комментарии. Остальное в `context.md` и правки человека не трогай.
4. **Анализ.** Только по `decisions.md`, `context.md` и нужным строкам BRD:
   - противоречия: решение против решения, решение против `R-xx`, решение против «Границ» `context.md`;
   - пропуски: требования из скоупа, у которых не определено поведение в исключениях — ошибка, недоступность смежного сервиса, пустое значение, повторный запрос, нет прав;
   - неоднозначности: формулировки, допускающие два прочтения.

   Каждое — новый вопрос по `question-routing.md`. Вместе с вопросом о скоупе из шага 3 это полный список: `python3 <плагин>/scripts/sa_ids.py next tasks/<KEY> Q-PO <N>` и отдельно `... Q-SA <N>`, по одному вызову на вид. Вопрос влияет на поведение для пользователя или на контракт между сервисами — `— *open, blocking*`, иначе `— *open*`. Вопрос, который решение сделало неактуальным, — `— *obsolete*`.

   Сразу запиши вопросы в `questions.md` (`Q-PO` — в `## Для PO`) и строки `?` в `context.md`.
5. **Проверка.** `python3 <плагин>/scripts/sa_validate.py tasks/<KEY>` — исправляй, пока не `OK`. Затем:
   - `python3 <плагин>/scripts/sa_state.py record tasks/<KEY> context impact-map`
   - стадия `start` или `clarify` → `python3 <плагин>/scripts/sa_state.py set tasks/<KEY> stage clarify`; стадия `draft` или `check` — не меняй (`/tdd-clarify` стадию не откатывает)
6. **Итог аналитику**, коротко:
   - «Закрыто N, новых M, открытых блокирующих K, нерешённый скоуп S»;
   - противоречия — по одной строке со ссылками;
   - блок для PO — вывод `python3 <плагин>/scripts/sa_questions.py export tasks/<KEY> PO` как есть, в блоке кода;
   - вопросы аналитику — вывод `python3 <плагин>/scripts/sa_questions.py export tasks/<KEY> SA`;
   - следующий шаг: K=0 и S=0 — `/tdd-draft` (стадия `draft`/`check` — `/tdd-update`, чтобы применить новые решения к черновику); иначе переслать вопросы и вернуться с ответами в `/tdd-clarify`.

## Чего не делать

- Не отвечай на вопросы за PO и не записывай догадки как решения.
- Не меняй и не удаляй прежние решения: новое решение, отменяющее старое, — новая строка со ссылкой на старый `D-xx` в тексте.
- Не перечитывай BRD и карту целиком.
