# /tdd-start [KEY] <формулировка>

Входы: `state.json`, `impact-map.md`, формулировка аналитика. Выход: `context.md`, если нужно — новые вопросы в `questions.md`; если в формулировке есть ответы на вопросы — решения в `decisions.md` и закрытые вопросы.

`<база>` — базовая директория этого скила, `<плагин>` = `<база>/../..`. Все команды — из рабочей папки аналитика.

Файлы задачи читай и пиши только по абсолютному пути `<tasks_dir>/<KEY>/…` (`tasks_dir` — из `sa_paths.py`), даже если ниже файл назван коротко (`questions.md`, `sources/BRD.md`).

## Перед началом

Прочитай `<плагин>/shared/rules/ai-rules.md`, `<плагин>/shared/rules/artifact-writing.md` и в `<плагин>/shared/schemas/artifacts.md` разделы context.md, questions.md и decisions.md. Не читай `sources/` и код.

Вопросы, ссылки, ID и таблицы пиши по `artifact-writing.md`.

## Шаги

1. **Папка задачи.** `python3 <плагин>/scripts/sa_paths.py` — возьми `tasks_dir`. Первый аргумент похож на ключ (`[A-Z][A-Z0-9]+-[0-9]+`) — `tasks/<KEY>`. Иначе: единственная задача в `tasks/` — она; несколько — спроси какую.
2. **Готовность.** `python3 <плагин>/scripts/sa_status.py tasks/<KEY>`. BRD неполный, нет `impact-map.md` или в «Устаревших входах» есть `BRD` — скажи об этом и предложи сначала `/tdd-impact`. Продолжай, только если аналитик подтвердит.
3. **Формулировка.** Возьми из неё цель, релиз, PO, название доработки, статус задачи, ссылки на Jira и дизайн, ограничения, ссылки на артефакты. Чего не хватает из цели, релиза, PO и статуса задачи — спроси одним сообщением списком и дождись ответа; не выдумывай. `release` и `po` обязательны и непусты.
   **Ответы на вопросы.** Формулировка отвечает на уже заведённые вопросы (`Q-SA-03: …` или явно по смыслу) — обработай их сразу, отдельный `/tdd-clarify` не нужен: шаги 2 «Разбор ввода» и 3 «Решения» из `<база>/../tdd-clarify/SKILL.md` (решения `D-xx` в `decisions.md`, закрытие и «Ответ в ТЗ» — командами `sa_questions.py`). Строки «Границ» по этим ответам ставь на шаге 5 сразу решёнными. Затем проверь новые решения по шагу 4 «Анализ» `/tdd-clarify` — противоречия (решение против решения, против `R-xx`, против границ), пропуски в исключениях и неоднозначности; найденное — вопросы в общий список шага 5, ID выдаются одной пачкой на шаге 6.
4. **Тип ТЗ.** `feature` — доработка существующих сервисов; `integration` — подключение внешней системы или платёжного метода. Допустимы только эти два типа. Не очевидно — спроси. Версия — из манифеста: `python3 <плагин>/scripts/sa_template.py version feature` печатает, например, `feature@2.0`; запиши ровно её: `python3 <плагин>/scripts/sa_state.py set tasks/<KEY> template feature@2.0`. Для `integration` манифеста пока нет (команда вернёт ошибку) — `integration@1.0`.
5. **Границы и противоречия.** Прочитай `impact-map.md` и отнеси каждую строку к `в скоупе`, `вне скоупа` (причина в Комментарии) или `?`, если из формулировки не следует. Проверь формулировку на противоречия с BRD и картой (например, `вне скоупа` для объекта, без которого не выполнить `R-xx`). Собери полный список новых вопросов — на каждый `?` и на каждое противоречие — и отнеси по `<плагин>/shared/rules/question-routing.md`: бизнес-решение — `Q-PO` (`[R-xx]`), техническая неясность — `Q-SA` (`[IM-xx]`); противоречие по умолчанию `Q-SA`. Вопрос, стоящий за строкой `?`, и вопрос о противоречии — всегда `— *open, blocking*`. Ссылку бери из карты: `Q-PO` — `R-xx` из колонки `← R` (допустим `IM-xx`), `Q-SA` — `IM-xx`.
6. **Вопросы.** Теперь, когда список полон: `python3 <плагин>/scripts/sa_ids.py next tasks/<KEY> Q-PO <N>` и отдельно `... Q-SA <N>` (по одному вызову на вид, N=0 — без вызова). Сразу допиши вопросы в `questions.md`: `Q-PO` — в `## Для PO`, `Q-SA` — в `## Для аналитика`. В Комментарий каждой строки `?` впиши ID её вопроса.
7. **Запись.** `context.md` по схеме. Если `context.md` уже есть (повторный запуск) — обнови его на месте: строки «Границ» — командой `python3 <плагин>/scripts/sa_context.py scope tasks/<KEY> <IM-xx…> "<скоуп>" ["<комментарий>"]`, остальное — точечно; сохрани правки человека и уже решённые строки, не переписывай с нуля.
   - Шапка (frontmatter), три ключа обязательны: `template` — `feature@2.0` или `integration@1.0` (совпадает с `state.json`), `release` — релиз или срок, непустой, `po` — кто PO, непустой.
   - Для шапки ТЗ («Статусы») — необязательные ключи: `title` — название доработки, заголовок страницы; `task_status` — `в аналитике`, `в оценке`, `в разработке` или `в стабилизации` (не назван — спроси, не выбирай сам); `jira` — голый URL задачи; `design` — ссылка на дизайн или `Не требуется`. Ключ `confluence` (pageId страницы) пишет только публикация.
   - `## Цель` — 1–3 предложения.
   - `## Границы` — таблица с колонками `← IM`, `Скоуп`, `Комментарий`. `← IM` — ровно один `IM-xx`, каждый `IM-xx` из карты ровно один раз. `Скоуп` — `в скоупе`, `вне скоупа` или `?`. `Комментарий` — причина для `вне скоупа` (обязательна); ID вопроса для `?`; иначе `—`.
   - Образец:

     ```markdown
     ---
     template: feature@2.0
     release: 2026-11
     po: Имя PO
     title: Запрет собственного промокода в анкете
     task_status: в аналитике
     ---
     # Контекст

     ## Цель

     Что и зачем, 1–3 предложения.

     ## Границы

     | ← IM | Скоуп | Комментарий |
     |---|---|---|
     | IM-01 | в скоупе | — |
     | IM-02 | вне скоупа | Причина |
     | IM-03 | ? | Q-PO-01 |
     ```
   - Необязательные `## Ограничения`, `## Допущения`, `## Ссылки` — пунктами, со ссылками на `R-xx`, `IM-xx`, `D-xx`, где применимо.
8. **Проверка.** `python3 <плагин>/scripts/sa_validate.py tasks/<KEY>` — исправляй, пока не `OK`. Затем:
   - `python3 <плагин>/scripts/sa_state.py record tasks/<KEY> impact-map`
   - `python3 <плагин>/scripts/sa_state.py set tasks/<KEY> stage start`
9. **Итог аналитику**, коротко: цель одной строкой; тип ТЗ; в скоупе N, вне скоупа M, не решено K; закрытые по ответам вопросы — ID и `D-xx`; новые вопросы — ID и строка; блок для PO — вывод `python3 <плагин>/scripts/sa_questions.py export tasks/<KEY> PO`, если есть открытые вопросы PO; следующий шаг — `/tdd-clarify`.

## Чего не делать

- Не перечитывай BRD и код: стадия работает только с картой влияния и формулировкой.
- Не решай скоуп за PO: неочевидное — `?` и вопрос.
