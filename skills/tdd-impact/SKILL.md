# /tdd-impact <ссылка или путь к файлу> [KEY]

Строит `tasks/<KEY>/`: `state.json`, `sources/BRD.md`, `impact-map.md`, `questions.md`; при повторном запуске с готовым `context.md` дописывает в него новые строки «Границ».

`<база>` — базовая директория этого скила, `<плагин>` = `<база>/../..`. Все команды — из рабочей папки аналитика.

Файлы задачи читай и пиши только по абсолютному пути `<tasks_dir>/<KEY>/…` (`tasks_dir` — из `sa_paths.py`), даже если ниже файл назван коротко (`questions.md`, `sources/BRD.md`).

## Перед началом

Прочитай `<плагин>/shared/rules/ai-rules.md`, `<плагин>/shared/rules/artifact-writing.md`, `<плагин>/shared/access/adapters.md` и в `<плагин>/shared/schemas/artifacts.md` разделы sources/BRD.md, impact-map.md, questions.md. Остальные справочники — только на шаге, который на них ссылается.

Вопросы, ссылки, ID и таблицы пиши по `artifact-writing.md`.

## Шаги

1. **Ключ задачи.** Второй аргумент — это ключ. Иначе возьми ключ Jira из ссылки (`[A-Z][A-Z0-9]+-[0-9]+`). Иначе спроси у аналитика ключ задачи и дальше не иди.
2. **Папка.** `python3 <плагин>/scripts/sa_paths.py` — возьми `tasks_dir` (и пути для шага 6). Если нет `tasks/<KEY>/state.json`: `python3 <плагин>/scripts/sa_state.py init tasks/<KEY> <KEY>`. Если есть — это повторный запуск (обычно после ответов PO на неполный BRD): переиспользуй существующие ID и не дублируй строки. Строки карты не удаляй: исчезнувший объект — `удал.` или как есть, чтобы строки «Границ» `context.md` (если он есть) оставались верными.
3. **BRD.** Получи текст по `adapters.md`: режим из `state.json`, иначе по порядку `mcp` → `cli` → `manual`. Путь к локальному файлу — это `manual`: прочитай файл. Запиши режим: `python3 <плагин>/scripts/sa_state.py set tasks/<KEY> access.jira <режим>` (или `access.confluence`). Связанные страницы читай, только если без них непонятны требования.
4. **Нормализация.** Запиши `sources/BRD.md` по схеме: шапка (`source` — ссылка или `manual`, `fetched` — сегодня, `brd_complete`, `missing` — заполняются на шаге 5), таблица требований. Одна строка — одно проверяемое требование; сжимай без потери условий, чисел и исключений. Тип — из списка схемы. Новые `R-xx` — по правилу «ID»; при повторном запуске старые не перенумеровывай.
5. **Полнота.** Пройди `<плагин>/shared/rules/brd-checklist.md`. Все обязательные пункты есть → `brd_complete: true`, `missing: []`. Не хватает обязательного пункта →
   - `brd_complete: false` и `missing: [...]` короткими названиями;
   - на каждый пункт — вопрос PO со ссылкой `[BRD]` в секции `## Для PO` файла `questions.md` по `<плагин>/shared/rules/question-routing.md`, статус `— *open, blocking*`; ID — `python3 <плагин>/scripts/sa_ids.py next tasks/<KEY> Q-PO <N>`, вопросы запиши в `## Для PO` сразу;
   - переходи сразу к шагу 9, карту не строй.
   
   Не хватает желательных пунктов → `Q-PO` с `[BRD]` и статусом `— *open*` (не blocking); BRD при этом полный.

   При повторном запуске вопросы `[BRD]`, которые закрыл обновлённый BRD, переведи в `— *answered*`.
6. **Кандидаты.** Пути возьми из вывода `sa_paths.py` (шаг 2): папка репозиториев, папка индекса, файлы индекса, сервисы (учитывает `SA_SYSTEM_DOCS` и `SA_REPOS_ROOT`). Если `repos_root … (нет)` — скажи аналитику, что папки репозиториев нет, и продолжай с `index_used: false`, `confidence_cap: средняя`, кандидатами только из BRD, без source-reader. Индекс системы — `bctc.md` (сценарии → сервисы) и `system_tech.md` (API и Kafka) в `index_dir`. Ищи grep-ом по ключевым словам требований по абсолютным путям из вывода, файлы целиком не читай. Итог — список сервисов-кандидатов и объектов в них. `index_files` не «нет» → `index_used: true`, `confidence_cap: высокая`. Иначе → `index_used: false`, `confidence_cap: средняя` (отметь в итоге аналитику), кандидаты — по `services` и поиску по ключевым словам в `<repos_root>/<сервис>`. Сервисы, которые ни одно требование не затрагивает, отбрасывай.
7. **Проверка в коде.** Для каждого сервиса-кандидата запусти субагента `sa-skills:source-reader` (инструмент Agent), всех — в одном сообщении, параллельно. В задании передай: абсолютный путь к репозиторию `<repos_root>/<сервис>`, требования `R-xx` с текстом, которые касаются сервиса, объекты-кандидаты, потолок уверенности (то же значение `confidence_cap`, что в шапке `impact-map.md`). Сам код не читай: работай с таблицами, которые вернули субагенты.
8. **Карта.** Собери `impact-map.md`:
   - строки субагентов;
   - объекты, которые следуют из BRD без кода (новый метод, роль, процесс), — статус `факт`, источник `BRD R-xx`;
   - дубли объединяй; уверенность не выше `confidence_cap`;
   - шапка: `index_used` и `confidence_cap` из шага 6;
   - `IM-xx` — по правилу «ID»; запиши карту сразу.

   Вопросы (по одному вызову `sa_ids.py next` на вид, `Q-PO` шага 5 уже записаны):
   - `допущение` с уверенностью `низкая` → `Q-SA`, ссылка `[IM-xx]`, где проверить;
   - заметки `source-reader` о смежном влиянии → `Q-SA` «входит ли <объект> в скоуп?» со ссылкой `[IM-xx]` или `[R-xx]`;
   - бизнес-неясности BRD → `Q-PO` со ссылкой `[R-xx]`;
   - `context.md` уже есть → каждый НОВЫЙ `IM-xx` допиши в его «Границы» как `?` с новым блокирующим `Q-SA` («входит ли <объект> в скоуп?», ссылка `[IM-xx]`), Комментарий = ID этого вопроса. Существующие строки не меняй.

   Маршрутизация — по `question-routing.md`.
9. **Проверка.** `python3 <плагин>/scripts/sa_validate.py tasks/<KEY>` — исправляй артефакты, пока не будет `OK`. Затем:
   - `python3 <плагин>/scripts/sa_state.py record tasks/<KEY> BRD`
   - `python3 <плагин>/scripts/sa_state.py set tasks/<KEY> stage impact`
10. **Итог аналитику**, коротко:
    - BRD полный или неполный (чего не хватает); если индекса нет — «индекса системы нет, уверенность ограничена «средняя»»;
    - карта: сколько объектов, сколько допущений, затронутые сервисы списком;
    - `not_services` из `sa_paths.py` не «нет» — одной строкой «не считаю сервисами (нет .git): …»: если среди них есть сервис без клона git, его код в карту не попал — аналитику стоит склонировать репозиторий и повторить `/tdd-impact`;
    - блок для PO — вывод `python3 <плагин>/scripts/sa_questions.py export tasks/<KEY> PO` как есть, в блоке кода;
    - открытые вопросы аналитику — ID и одна строка;
    - следующий шаг: `/tdd-start`, а при неполном BRD — переслать вопросы PO и после ответов запустить `/tdd-impact` повторно.


Последней строкой итога — предложение следующего шага по `<база>/../sa-flow/SKILL.md`, раздел «Что предлагать» («Дальше — … Запускаю?»; в точке остановки — что нужно от аналитика). Следующую стадию сам не запускай — только после согласия аналитика.

## Чего не делать

- Не читай код и большие страницы в свой контекст — для этого `source-reader`.
- Не выдумывай объекты и источники; нет источника — `допущение`.
- Не задавай PO технических вопросов.
- Не меняй файлы в репозиториях сервисов.
