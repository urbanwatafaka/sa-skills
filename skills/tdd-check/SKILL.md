# /tdd-check [KEY] [--code]

Входы: вывод `sa_review.py`, прошлый `review.md`; черновик, BRD, карту, решения и чек-листы читает ревьюер. Выход: `review.md`.

`<база>` — базовая директория этого скила, `<плагин>` = `<база>/../..`. Все команды — из рабочей папки аналитика.

## Перед началом

Прочитай `<плагин>/shared/rules/artifact-writing.md` и в `<плагин>/shared/schemas/artifacts.md` раздел «review.md». Черновик сам не читай и не правь — его читает ревьюер. `review.md` пиши только по абсолютному пути `<tasks_dir>/<KEY>/review.md`.

## Шаги

1. **Папка задачи.** `python3 <плагин>/scripts/sa_paths.py` — возьми `tasks_dir`, `repos_root`, `services`. Первый аргумент похож на ключ (`[A-Z][A-Z0-9]+-[0-9]+`) — `tasks/<KEY>`; иначе единственная задача в `tasks/`, при нескольких — спроси. `--code` во вводе включает шаг 5. Вместо ключа дали ссылку на страницу Confluence — скажи, что ревьюится локальный `draft.md`, и продолжай по ключу. `python3 <плагин>/scripts/sa_status.py tasks/<KEY>`: стадия должна быть `draft`, `check` или `done`, иначе скажи сначала запустить `/tdd-draft` и остановись.
2. **Валидатор.** `python3 <плагин>/scripts/sa_validate.py tasks/<KEY>`. Ошибки не только в `review.md` — покажи их, предложи `/tdd-update` (или `/tdd-draft`) и остановись. Ошибки только в `review.md` — продолжай: файл перепишешь на шаге 6.
3. **Проходы скрипта.** `python3 <плагин>/scripts/sa_review.py precheck tasks/<KEY>` — первая строка `draft: <sha1>`, дальше таблица замечаний: шаблон, плейсхолдеры, покрытие `R` (типа `функц.` и `UI`) критериями приёмки в таблице User Stories и `IM` секциями. `python3 <плагин>/scripts/sa_review.py coverage tasks/<KEY>` — матрица покрытия.
4. **Ревьюер.** Если `review.md` есть — прочитай его: замечания `открыто` и `принято` — «проверить», `отклонено` — «не поднимать», `round` — номер прошлого прохода. Вызови субагента `sa-skills:tdd-reviewer` одним заданием:
   - абсолютные пути: `<tasks_dir>/<KEY>/draft.md`, `<tasks_dir>/<KEY>/sources/BRD.md`, `<tasks_dir>/<KEY>/impact-map.md`, `<tasks_dir>/<KEY>/decisions.md`; манифест — в папке `<плагин>/shared/templates/`, файл по типу шаблона (тип — из строки «шаблон» статуса, до `@`) с расширением `.yaml`; папка блоков `<плагин>/shared/blocks/`;
   - таблица из вывода `precheck` — «уже найдено, не повторяй»;
   - «проверить» и «не поднимать» — строками `ID — Где — Проблема`.
   Ответ — две таблицы: новые замечания и вердикты по прошлым.
5. **Сверка с кодом** — только с `--code`. `python3 <плагин>/scripts/sa_review.py asis tasks/<KEY>` — утверждения о существующем по сервисам: `[сохраняется]` и `[существует]`. Сервис есть в `services` — по субагенту `sa-skills:source-reader` на сервис, параллельно, в режиме сверки: путь `<repos_root>/<сервис>` и утверждения этого сервиса. Сервиса нет среди репозиториев или группа `без сервиса` — не сверяй, упомяни в итоге. Подписи интерфейса: из `### Front` в `draft/03-changes.md` и «Требований к UI» в `draft/01-brd.md` выпиши названия существующих экранов, вкладок, полей и кнопок в «ёлочках» (не новые тексты) и проверь их одним вызовом на фронт: `python3 <плагин>/scripts/sa_locale.py find <repos_root>/<фронт> "<подпись>"…`. Нет точного совпадения (`=`) — новое замечание `совет`: Где — секция, Проблема — «подписи «…» нет в интерфейсе» и похожая подпись (`~`), если есть. Вердикт `опровергнуто` — новое замечание `важно`: Где — секция утверждения, ← Ссылка — `IM-xx` из утверждения, Проблема — «не подтверждается кодом: <источник и фраза>»; `не найдено` — `совет`.
6. **review.md** — только командой, файл руками не пиши.
   - Собери JSON во временный файл в папке задачи `<tasks_dir>/<KEY>/review-input.json`: `{"new": [...], "close": [...]}`. `new` — замечания ревьюера и сверки с кодом, каждое `{"severity", "where", "problem", "ref", "proposal"}` (`ref` без ссылки — `—`); замечания `precheck` не передавай — команда добавит их сама. `close` — ID прошлых `открыто` и `принято`, по которым ревьюер дал вердикт `закрыто`.
   - `python3 <плагин>/scripts/sa_review.py write tasks/<KEY> <tasks_dir>/<KEY>/review-input.json`. Команда сохраняет прошлые строки, закрывает замечания `precheck`, которых больше нет, и `открыто` с исчезнувшим ID, пропускает дубли, выдаёт ID новым и пишет шапку и матрицу покрытия. Вывод — `round`, закрытые, новые и число открытых: он нужен для итога.
   - Удали `review-input.json`.
7. **Проверка.** `python3 <плагин>/scripts/sa_validate.py tasks/<KEY>` — исправляй `review.md`, пока не `OK`. Затем `python3 <плагин>/scripts/sa_state.py record tasks/<KEY> draft` и `python3 <плагин>/scripts/sa_state.py set tasks/<KEY> stage check`.
8. **Итог аналитику**, коротко:
   - число замечаний по важности; при повторном запуске — закрыто N (ID), осталось M (ID), новых K;
   - критичные — списком: ID, где, проблема;
   - строки матрицы без историй (для `R` типа `функц.` и `UI`);
   - с `--code` — какие сервисы не сверены;
   - следующий шаг: принять и внести — `/tdd-update RV-01 RV-03` или `/tdd-update все`; отклонить — `/tdd-update отклонить RV-02`; после правок — снова `/tdd-check`. Замечаний `открыто` и `принято` нет — ТЗ готово: `python3 <плагин>/scripts/sa_state.py set tasks/<KEY> stage done`.

## Чего не делать

- Не правь черновик, секции, `draft.md` — только `review.md`.
- Не меняй ID и тексты прошлых замечаний.
- Не ставь `принято` и `отклонено` сам — это решение аналитика.
- Не читай код сам — только через `source-reader` в режиме сверки.
