# /sa-index-docs [сервис|all] [--full]

Входы: код репозиториев сервисов (читает субагент), вывод `sa_index.py`. Выходы: `<repos_root>/<сервис>/docs/sa-index/` и глобальные файлы в `index_dir`. Только файлы в рабочую копию, без веток и коммитов: что коммитить и как делать MR — решают разработчики сервиса.

`<база>` — базовая директория этого скила, `<плагин>` = `<база>/../..`. Все команды — из рабочей папки аналитика.

## Перед началом

Прочитай `<плагин>/shared/index/docs-schema.md`. Код сам не читай — его читает `docs-indexer`. Файлы `docs/sa-index/` сам не пиши. Остальные файлы `docs/` — документация разработчиков, их не трогает никто.

## Шаги

1. **Пути.** `python3 <плагин>/scripts/sa_paths.py` — `repos_root`, `services`, `index_dir`. `repos_root … (нет)` — скажи, что папки репозиториев нет (`SA_REPOS_ROOT`), и остановись.
2. **Цели.** Аргумент — имя из `services`: этот сервис; `all` — все `services`; нет аргумента — покажи `services` и спроси. Имени нет в `services` — покажи список и остановись. `--full` во вводе — полный проход для всех целей.
3. **Карта.** По каждой цели `python3 <плагин>/scripts/sa_index.py survey <repos_root>/<сервис>`. Строка `branch` содержит `ОТСТАЁТ` — предупреди аналитика, что индекс будет по устаревшей ветке, `pull` не делай. Режим сервиса — `mode` из `survey`, при `--full` — полный.
4. **Правки человека.** Соберите все файлы `docs` со статусом `правка человека` в сервисах с полным режимом и спроси аналитика одним вопросом: перезаписать или оставить. Оставить — этот файл субагенту не передавай и предупреди сразу: если оставленный файл не по схеме, `check` его не пропустит и сервис не будет отмечен; выход — аналитик переименует его в `docs/sa-index/<имя>.bak.md`, и только потом субагент пишет новый файл. В инкрементальном режиме не спрашивай: субагент правит только строки по изменённым файлам.
5. **Изменения.** Для инкрементальных: `python3 <плагин>/scripts/sa_index.py changed <repos_root>/<сервис>`. `files` = `нет` и все три файла `docs` есть — сервис актуален, субагента не вызывай (переходи к шагу 7). Файла `docs` нет или он в строке `invalid` — для него полный проход, сервис не «актуален».
6. **Субагенты.** По `sa-skills:docs-indexer` на сервис — при нескольких целях вызовы одним сообщением, параллельно, не больше 4 за раз. Режим передавай по файлу («tech.md — инкрементально; DB.md — полный»). Если в `survey` `split: да` и режим полный — вместо одного три субагента на сервис, по файлу каждому. В задании:
   - `<repos_root>/<сервис>` и путь плагина `<плагин>`;
   - вывод `survey` как есть;
   - файлы, которые писать в `<repos_root>/<сервис>/docs/sa-index/` (без оставленных на шаге 4);
   - режим; для инкрементального — вывод `changed` как есть;
   - если в `index_dir` есть `bctc.md` — путь к нему: «имена сценариев бери оттуда».
7. **Проверка и отметка.** По каждому сервису `python3 <плагин>/scripts/sa_index.py check <repos_root>/<сервис>`. Ошибки — передай их тому же субагенту на исправление один раз; остались — сервис не отмечай, перечисли ошибки в итоге; если ошибки только в оставленных файлах — скажи, в каких, и что отметка пропущена. `OK` — `python3 <плагин>/scripts/sa_index.py stamp <repos_root>/<сервис>`.
8. **Глобальные файлы.** `python3 <плагин>/scripts/sa_index.py aggregate`. Вывод говорит, что файл не собран скриптом и не перезаписан, — покажи аналитику и спроси, перезаписать ли; да — `python3 <плагин>/scripts/sa_index.py aggregate --force`. Предупреждения о пропущенных файлах — в итог.
9. **Итог аналитику**, коротко:
   - по сервису: режим, строки по файлам и ячейки с `?` (из ответа субагента), отмечен ли;
   - актуальные сервисы без изменений;
   - сервисы с ошибками `check` и пропущенные `aggregate` файлы;
   - что изменились рабочие копии `<repos_root>/<сервис>/docs/sa-index/` и `index_dir`: коммит и MR — на стороне разработчиков сервиса;
   - ячейки с `?` стоит проверить с разработчиками.

## Чего не делать

- Не читай код и не пиши `docs/sa-index/` сам — только через `docs-indexer`.
- Не делай `git checkout`, `commit`, `pull`, `push`, не создавай ветки.
- Не правь `docs/sa-index/.sa-index.json` и глобальные файлы руками — их пишут `stamp` и `aggregate`.
